id: zcode-silent-snapshot-upload-audit
type: incident
title: ZCode v3.12.3 silently uploaded full git history; v3.14.3 source verified clean
status: active
claim: The closed-source ZCode desktop client (≤ v3.12.3, and per upstream's own docs still in current closed-source builds) silently packaged entire workspaces — including full `.git` history, LFS caches, and reflogs — encrypted them with a server-controlled RSA key, and uploaded them to Alibaba Cloud OSS whenever the user was logged in, with no opt-out. In the open-source checkouts v3.14.3 (29628c9) and v3.15.1 (aac4755) the entire upload pipeline is verifiably absent: checkpoints are pure local Git, code indexing is local ripgrep/bfs/ugrep, and the only outbound data flows are model-inference context, aggregated ARMS network metrics, user-initiated feedback attachments / conversation-share publishes, a JWT-authenticated "highspeed draw" API, marketing-touch telemetry, download-only cloud-content bundles, and the official auto-update feed. Building the desktop app from this source removes the exposed behavior, provided the auto-update feed is disabled or self-hosted so the audited binary is not silently replaced by official builds.
scope.paths:

evidence:
  - Snapshot upload pipeline absent: grep across repo at 29628c9 finds no `/api/v1/snapshot/upload-credential`, no `repoSnapshot`, no `captureBeforePrompt`, no `repo-wiki`, no `repo_snapshot_extra_manifest`, no `settings.behavior.json` hashing. Only benign matches: `packages/services/src/feedback/feedbackHttpClient.ts` (user-initiated feedback ticket attachment upload) and a route-segment allowlist entry in `packages/desktop/src/main/networkTelemetryAggregator.ts`.
  - Envelope-encryption upload code absent: no `rsa-oaep`, `publicKeySpkiPem`, `x-oss-signature`, or AES-256-CTR workspace encryption outside `feedbackHttpClient.ts` (feedback attachments only).
  - Checkpoints are local-only: `packages/services/src/git/gitCheckpointService.ts`, `createGitCheckpointService()` uses local Git CLI via `gitCheckpointRepo`/`gitCheckpointStore`, metadata saved as local JSON, no network calls.
  - Code indexing is local: native search tools (ripgrep 14.1.1, bfs 4.1.1, ugrep) bundled with SHA256 checksums in `apps/zcode-cli/dependencies/native-search/SHA256SUMS`; all search runs as local processes.
  - No workspace packaging for upload: all tar.gz/zip code paths are build/release tooling (`scripts/`, `packages/zcode-server-cli`) or remote-server deployment to the user's own SSH hosts (`packages/server/src/remote/`).
  - Outbound telemetry is metrics-only: `packages/desktop/src/main/networkTelemetryAggregator.ts` aggregates latency/error counters with a static route-segment allowlist (comment at line 63 explains it prevents leaking user paths/slug/email); sends device_mid, platform, app_version — no file content.
  - Auto-update feed points to official CDN: `packages/desktop/src/main/autoUpdater.ts` (default `autoUpdater.autoDownload = false` at line 1501, but polls official feed; `autoUpdaterDisabledForProductFlavor` hook at line 1464 can disable it).
  - Fork HEAD matches upstream: local HEAD 29628c9acdb81b703bbd4080c207a0e7ce5e276e confirmed identical to current zai-org/ZCode HEAD via GitHub API on 2026-09-26.
  - v3.15.1 re-audit (2026-10-11, upstream commit aac4755, one 11.7k-file squashed commit): all v3.12.3 markers absent from code. `packages/services/src/repo-snapshot/` does not exist in the tree; `repoSnapshotUploadClient.ts` appears only in upstream's own `docs/analysis/credentials-json-code-audit.md`, which documents the closed-source tree (open-source docs reference closed-source code). No code matches `repoSnapshot` / `captureBeforePrompt` / `rsa-oaep` / `publicKeySpkiPem` outside docs.
  - v3.15.1 confirms closed-source binary still uploads: `docs/analysis/memory-leak-audit-2026-09-03.md` (shipped by the vendor) states the closed-source desktop packaged, sha256'd, AES-encrypted and attempted to upload a `.tar.gz.enc` of the workspace on every prompt send and turn end, including `.git/` internals (`.git` unconditionally whitelisted in `repoSnapshotFilter.ts`, bypassing size caps), accumulating GBs of pending uploads under `~/.zcode/v2/checkpoints/*/pending`. Never accept an official binary.
  - v3.15.1 deep sweep of all archive+send paths: (1) feedback attachments unchanged; (2) conversation-share upload (new) is UI-button-triggered only (`ConversationShareMenu.tsx` → protocol channel `conversation-share`), uploads only user-selected artifacts with size caps and SHA-256 re-verify against selected bytes, no workspace scan; (3) remote deploy tarballs go only to user-configured SSH hosts; (4) highspeed draw is JSON-only POST to `<origin>/api/v1/highspeed/draw` with ZCode JWT + coding-plan headers.
  - v3.15.1 new outbound surfaces (all audit-passed): `marketing-touch` service sends device_mid/locale/app-version/campaign clicks to `/api/v1/marketing/touch`; `cloud-content` service is download-only (HTTPS-only allowlist from server-verified responses, sha256-pinned, size-capped, `redirect: "error"`, served from a local 127.0.0.1 lease server); `networkTelemetryAggregator.ts` diff is export-keyword only.
  - v3.15.1 `.git`-internals check: grep for `.git/objects|\.git/logs|repoSnapshotFilter` across packages/ and apps/ — zero code hits. Only `createCipheriv` uses are local credential storage (`credentialCipherProvider.ts`) and OAuth token decryption.
  - v3.15.1 plugin sandbox: new code is registration-bridge lifecycle plumbing; plugins render in an isolated sandboxed webview shell, no permission loosening found.
  - v3.15.1 `autoUpdater.ts` heavily rewritten (243 lines changed): `enabled: false` disable hook survives (`initAutoUpdater` → `autoUpdaterDisabledForProductFlavor`), so the fork's patch pattern still applies but will conflict on merge.
  - Audit limits: targeted grep + tracing of every upload trigger, not line-by-line review of 1.9M added lines; verified against commit aac4755 only (upstream history is wiped — every future sync needs this audit repeated).
