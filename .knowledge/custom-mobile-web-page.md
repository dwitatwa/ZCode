claim: The self-hosted web server ships a dedicated custom mobile page at `/mobile.html` (second vite entry in `packages/web`), freely customizable by the fork owner. v3 UI: **antd-mobile 5.43 + lucide-react** (desktop's icon set) over the same three-screen architecture — bottom adm TabBar (Explorer / Chat / Info, Badge dot for pending permissions), NavBar per screen, CapsuleTabs workspace picker, SwipeAction + Popover menu for archive/delete with Dialog.confirm, Collapse archived section, adm TextArea composer with chips, ProgressCircle context meter, List-based KV panels, Toast for all errors (no more alert()). Dark theme = `--adm-*` variable overrides in `src/mobile/mobile.css` (loaded after `antd-mobile/es/global/global.css`). **React 19 compat (critical)**: antd-mobile imperative components (Dialog.confirm / Toast.show / ActionSheet.show) are silent no-ops under React 19 because rc-util's renderer falls back to removed `ReactDOM.render` (React 19 moved `createRoot` to `react-dom/client` only) — fixed by `src/mobile/lib/adm-react19.ts` calling `unstableSetRender` with a createRoot implementation (official v5-for-19 shim; types in `src/mobile/antd-mobile-compat.d.ts`); imported first in main.tsx. All composer data comes from snapshot `configOptions` server projection (model option id `model` entries carry `modelProviderId`/`modelThoughtLevels`/`modelDefaultThoughtLevel`; `thought_level` option carries per-model levels); `parseModelPickerValue` (`@zcode/shared/model-selection`) turns entry values back into `{providerId, modelId}`. Per-submission draft semantics match desktop: `sendPrompt` carries `mode` (build/edit/plan/yolo) and `modelSelection.options.reasoningLevel`. `taskId` === agent `sessionId` (zcode-task-types-core) so Info-screen v4 queries call it directly with the task id.
